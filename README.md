## Структура решения

Пайплайн разбит на 5 ноутбуков, каждый — отдельный этап, с файлами на входе/выходе:

| # | Ноутбук | Что делает | Вход → Выход |
|---|---|---|---|
| 1 | `01_eda.ipynb` | EDA: распределения, пропуски, корреляции, проверка гипотез | `train.csv`, `test.csv` → инсайты (текст) |
| 2 | `02_baseline.ipynb` | Baseline: минимальная обработка + LogisticRegression | → `submission_baseline.csv` |
| 3 | `03_feature_engineering.ipynb` | Новые признаки, умная импутация, проверка на CV | → `train_fe.csv`, `test_fe.csv` |
| 4 | `04_models_tuning.ipynb` | 4 модели + тюнинг гиперпараметров (Optuna) | → `oof_predictions.csv`, `test_predictions.csv` |
| 5 | `05_ensemble_final.ipynb` | Voting / weighted voting / stacking, финальный submission | → `submission_final.csv` |

## Подход: baseline → итерации → финал

| Этап | CV accuracy |
|---|---|
| Baseline (LogReg, минимальная обработка) | 0.7853 |
| + Feature Engineering (LogReg) | 0.7963 |
| XGBoost (tuned) | 0.8119 |
| LightGBM (tuned) | 0.8117 |
| CatBoost (tuned) — лучшая одиночная модель | 0.8126 |
| **Финальный ансамбль (stacking, 3 бустинга)** | **0.8130** |

Итоговый прирост от baseline: **+2.77 п.п.**

Кросс-валидация везде одна и та же: `StratifiedKFold(n_splits=5, shuffle=True, random_state=42)`, метрика — accuracy (как в соревновании).

## Что сработало лучше всего

- **Умная импутация вместо медианы/моды.** Из EDA: `CryoSleep=True` у 100% пассажиров означает нулевые траты без единого исключения — использовали это для взаимной импутации `CryoSleep`↔траты. `HomePlanet` внутри одной группы (`PassengerId` → `GroupId`) всегда одинаковый, а `Deck` почти детерминирует `HomePlanet` — импутация каскадом группа → Deck → мода закрыла почти все пропуски осмысленно, а не вслепую.
- **Разбор `Cabin` на `Deck`/`CabinNum`/`Side`.** `Deck` оказался одним из сильнейших предикторов таргета (73% Transported на Deck B против 20% на Deck T).
- **`GroupSize`/`IsAlone`/`IsChild`.** Одиночки переносятся реже среднего, дети до 13 лет — значительно чаще взрослых.
- **Переход с LogisticRegression на бустинги.** Основной прирост качества (0.7963 → 0.8126) пришёл именно отсюда — данные с нелинейными взаимодействиями, линейная модель их не ловит.
- **Исключение слабой модели из ансамбля.** Простое усреднение всех 4 моделей было хуже лучшей одиночной; убрав `LogisticRegression`, усреднение трёх бустингов сразу обошло CatBoost.

## Что не сработало

- **log1p-трансформация трат для LogisticRegression.** Ожидали улучшения (данные сильно скошены, много нулей), получили ухудшение: 0.7937 → 0.7806 на той же конфигурации признаков. В финальный набор log-версии не включали.
- **`CabinNum` и `TotalSpend` как дополнительные признаки для LogisticRegression** — не дали прироста (0.793-0.794 против 0.7963 без них).
- **Voting по всем 4 моделям.** Слабая `LogisticRegression` (0.7963) тянула средний результат вниз (0.8093) — хуже, чем просто взять лучшую одиночную модель (CatBoost, 0.8126).
- **Ансамбль в целом дал меньше, чем ожидалось.** `xgb`/`lgbm`/`cb` коррелируют между собой на 0.986–0.991 — то есть это почти одна и та же модель с разными названиями. Stacking по трём бустингам дал лишь +0.04 п.п. над лучшей одиночной моделью.

## Известные пробелы

- Не проверено сравнение `StratifiedKFold` vs `GroupKFold` по `GroupId` — в EDA была гипотеза, что члены одной группы могут коррелировать по таргету и завышать обычную CV-оценку; экспериментально не подтверждено и не опровергнуто.
- Не просмотрены публичные топовые ноутбуки и discussions по соревнованию — стоит сделать перед финальной сдачей, как того требует чек-лист.
- Public LB score пока не зафиксирован — CV может разойтись с реальным результатом на паблик-лидерборде, нужно сверить после сабмита.

## Как воспроизвести

1. Скачать `train.csv`, `test.csv`, `sample_submission.csv` со страницы соревнования, положить в одну папку с ноутбуками.
2. Установить зависимости:
```bash
   pip install pandas numpy scikit-learn matplotlib seaborn xgboost lightgbm catboost optuna
```
3. Выполнить ноутбуки по порядку — 01 → 02 → 03 → 04 → 05. Каждый следующий использует файлы, сохранённые предыдущим (см. таблицу структуры выше).
4. Финальный файл для сабмита — `submission_final.csv`, из `05_ensemble_final.ipynb`.

Все random_state зафиксированы (включая seed сэмплера Optuna), результаты воспроизводимы при повторном запуске.
